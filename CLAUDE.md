# Deliver My Baby — BACKEND (game server)

Frontend (3D client) lives at `../Deliver-my-baby` (`src/net.js`, `src/remote.js`, `src/queue.js`, `src/store.js`). Colyseus + Mongo, ported from `C:\ThreeJS\Dont-miss-your-flight\Dont-miss-your-flight-backend` (same identity, saves, presence, server-ordered lines and Bloxity reporting). A contract change goes in both projects.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`, Bloxity faked via `__setVerifierForTest` / `__setRewardVerifierForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`), `maxClients` = `ROOM_MAX_CLIENTS` (50 = Bloxity's default seatCap). Client calls `joinOrCreate("world", { token, username, pfp, pose, trip, avatar })`. Client-authoritative gameplay: the server only bounds saves (`src/sanitize.ts`) and presence (`src/presence.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable. `/health` for Legion; `/monitor` and the playground are dev-only.

## Identity (src/bloxity.ts)
- A signed-in player sends `Legion.SDK.auth.getToken()` as `token`; the server POSTs `{BLOXITY_API_URL}/v1/auth/game-token/verify` (Bearer token, body `{ gameSlug }`) and uses ONLY `user._id` as the account id. A bad / missing token = guest (never saved). A client-sent `userId` is trusted only outside production (`trustClientIds()`: `NODE_ENV !== "production"` and no `BLOXITY_ENV`) so local dev (`dev-...` ids) and the tests keep a save.
- `identify` (same shape) re-identifies after a sign-in / sign-out; `progress` / `noProgress` carry `you` { signedIn, username, uid }. A second live session on the same account evicts the first (closed CONSENTED with reason `REPLACED_REASON` "replaced": that client does not rejoin until its player returns to it, so two tabs never ping-pong).

## Saves
- `saveProgress` (client store.snapshot()): `coins`, `twins`, `babies` [{ name, type, shiny? }] (the latest `BABIES_MAX`, names cut to `BABY_NAME_MAX`), `trips` and `delivered` (both `$max`, never drop), the Babydex `dex` { [type]: { n, s } } (at most `DEX_TYPES_MAX` types, shiny <= delivered), `dexClaimed` (keys matching `DEX_CLAIM_PATTERN`, at most `DEX_CLAIMS_MAX`) `pity` (<= `PITY_MAX`) the permanent upgrades `upg` { [id]: level } (at most `UPGRADES_MAX` ids, levels 1..`UPGRADE_LEVEL_MAX`), `earned` (lifetime coins, `$max`), `swaddles`, `decor` (ids) and today's `missions`. The Daily Reward calendar (`src/daily.ts`, ported from Dont Miss Your Flight: `dailyDay` / `dailyLast` / `dailyClaimed`) is written by the server only: `claimDaily` { day } -> `dailyResult`, `dailyRefresh` -> `daily` (also sent on load). `brag` { type, rarity, shiny } -> `bragged` to everyone else (one per `BRAG_COOLDOWN_MS`). Presence `trip.dex` = Babydex types found (`PlayerState.dex`). Leaderboards add `babies_week` (a weekly `sum` board: each report adds the babies delivered since the last, `weekBase`) and `earned`. The number of `dex` types is tracked for the `dex_12` / `dex_all` badges (`DEX_TOTAL` = the client's catalog size). Answers on load: `progress` (sanitized doc) / `noProgress` / `serverError` (read failed: saving stays off). Saves are ignored until the session's load answered. `playtime` (s) is counted by the server and written on leave; `lastSeen` too.
- Rewarded ads: `adReward` { rewardToken } -> POST `/v1/ads/reward/verify` { gameSlug, rewardToken } -> `adRewardResult` { ok, coins: `AD_REWARD_COINS`, test } or { ok: false, reason } (one per `AD_REWARD_COOLDOWN_MS` = client `ADS.reward.cooldown`, which plays no ad before it ran out; a token for another account is refused). The client grants the coins.
- Trolls (Kill / Kill All on real moms): `troll` { id, text } -> broadcast `trolled` { id, from, sid, text } to everyone else, one per `TROLL_COOLDOWN_MS` (client `NET.trollCooldown` / `canTroll()` refuses a Kill before charging for one this would drop), text cut to `TROLL_TEXT_MAX`. Kill: text = the target's session; Kill All: text = the line (each receiver compares her ticket with the sender's, looked up by `sid` on the roster).

## Fellow moms (roster = `WorldState.players`, src/presence.ts)
- `PlayerState`: `username`, `signedIn`, `uid`, `pfp`; pose `x`/`y`/`z`/`yaw`/`speed`/`grounded`/`anim` ("" | sit | phone | shock | ko | lie); trip `zone` (street | lobby | waiting | breathing | ultrasound | final | solo), `line` + `ticket` (server-set), `hold` ("lobby:N" | "<room>:0"), `belly`, `twins`, `carry` ("type:Name,type:Name", `CARRY_PATTERN`); `away` / `idle` (server-set); `emote`; `avatar` (Bloxity look JSON, max `AVATAR_MAX_LEN` = client `NET.avatarMax`, never parsed; the client drops the proportions, or the whole look, rather than cut it).
- Messages: `pose` (~10/s, bounds `POSE_BOUNDS`), `trip` (on change), `emote` { id }, `setAvatar` { avatar }. The join options may carry `pose`, `trip`, `avatar`.
- **Lines** (`src/lines.ts`, `test/Lines.test.ts`): one per hospital room (`LINE_KINDS`). `line` + `ticket` are server-owned (a `trip`'s `line` is ignored). `joinLine` { kind } = a ticket at the back, `leaveLine`, `skipLine` { kind } = ahead of everyone, `cutLine` { kind, past } = ahead of the `past` real moms right in front (capped by `CUT_PAST_MAX`). `callMe` { kind, keys } -> `called` { kind, key }: one of the first `CALL_DEPTH` waiting moms (away / idle passed over) gets the first free offered spot of that line (`LINE_SPOTS`) if enough are free for her place; she leaves the line and `hold`s it. A spot is taken while someone present (not away / idle) holds it, or was handed it within `SPOT_GRACE_MS`.
- `idle`: no `active` message for `IDLE_AFTER_MS` (only clients that sent one once). `away`: `alive` beats stopped for `AWAY_AFTER_MS` (checked every `AWAY_CHECK_MS`), an `away` { on } message, or a dropped connection waiting `RECONNECT_SECONDS` (`test/Away.test.ts`).

## Bloxity reporting
- Every `REPORT_EVERY_MS` the room reports its signed-in players: leaderboards (`BOARDS`: babies, trips, coins; POST `/v1/leaderboards/hosted/{BLOXITY_GAME_ID}/report`, user ids `legion_<id>`, boards declared on the first call; only changed scores; a leaving / account-switching / shut-down session's last scores go at once; `test/Leaderboard.test.ts`) and game stats (`STATS`; POST `/v1/games/{BLOXITY_GAME_ID}/stats`, clamped under Bloxity's ceilings). Both need `BLOXITY_REPORT_TOKEN` + `BLOXITY_GAME_ID`. The client declares the same boards (`LEADERBOARDS` in config.js).
- Open Rooms (`src/roomReporter.ts`, `installRoomReporter()` after `listen`): every 2 s POST `{MATCHMAKER_REPORT_URL}/{BLOXITY_GAME_ID}/rooms` { podName, players, rooms[] } (private rooms skipped).
- Env (injected by Bloxity hosting, see `.env.example`): `BLOXITY_ENV`, `BLOXITY_API_URL`, `BLOXITY_GAME_ID`, `BLOXITY_REPORT_TOKEN`, `MATCHMAKER_REPORT_URL`, `POD_NAME`, `MONGODB_URI`, `CLIENT_ORIGIN`, `PORT`.

## CI/CD
`.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev) with { channel, image, version } only: no room size / seatCap is sent, Bloxity's default seatCap 50 = `ROOM_MAX_CLIENTS`. Needs secret `LEGION_DEPLOY_TOKEN`; `LEGION_GAME_ID` (var/secret) defaults to `deliver-my-baby`. After the first push make the GHCR package public. On SIGTERM `WorldRoom.onBeforeShutdown` stamps everyone's save and disconnects them; the clients re-resolve through the matchmaker.
